# 如果乔布斯来看 Aside

> 2026-08-13 的一次设计评审，用「乔布斯会怎么改」当视角。
> 结论不是标准答案，是一份待决策清单——先回答里面的问题，再动代码。

## 一句话诊断

他会先问：**「这个 app 是干什么的？」** 然后掐着表等一句话的回答。

现在的诚实答案是：「记东西，自动分类，还能当待办、当读书摘抄、当灵感本，
还能置顶、高光、隐藏、回复。」——这句话说不完，就是要动刀的地方。

---

## 观察一：「重要」这件事有三个说法

```
高光 hl ──┐
摘抄 qt ──┼── 三个都在说「这条不一样」，用户要记住三种手势、三种样式
置顶 pin ─┘
待办 td ──── 第四种：这条要做
隐藏 msk ─── 第五种：这条别看

一条记录能同时是：高光的 + 摘抄的 + 置顶的 + 待办的 + 隐藏的
                 + 回复别人的 + 带图的 + 被筛选的
   = 2^7 种状态组合，自己都测不完
```

**他会留「待办」和一个「重要」，其余砍掉。**

代码位置：`toggleMark()`（index.html:1838）一个函数管 hl/qt/pin/msk 四种；
长按菜单第一组（index.html:1781）现在 8 项。三合一之后掉到 5 项。

要考虑的代价：

- `qt`（摘抄）不只是样式，它还联动「摘抄」标签，导出 Markdown 时排成 blockquote
- `pin`（置顶）有独立的置顶条 `renderPinBar()`（index.html:1857）
- `msk`（隐藏）是给别人看屏幕时遮正文用的，和「重要」不是一类，砍它要单独决定

## 观察二：产品定位分裂——空状态那句话和标签表打架

空状态文案（index.html:1245）：

```
记点什么吧
吃了什么、动了多久、身体什么感觉
```

**这是全 app 最好的一行文案**，它把产品定义得清清楚楚：一个身体日志。

但 `SEED_TAGS`（index.html:950）里有「摘抄」「念头」「其他」，
再加上 OCR 扫书页、Markdown 导出、回复串——全是另一个产品的零件（第二大脑）。

他的选择会是：**就做那句话说的事**。饮食 / 运动 / 身体感受，三个标签，其余删掉。
因为聚焦，才能做到通用记事本永远做不到的事：

> 「你连续四天晚饭后记了胃胀，那四天都吃了外食。」

6 个标签的通用记事本永远算不出这句话。

⚠️ 这是本文档里唯一一条**不可逆**的建议：删标签会动到已有记录（`deleteTag()`
会把记录归到兜底标签）。先想清楚「摘抄」和「念头」到底还用不用，再决定。

## 观察三：这个 app 只能「存」，不能「还」

```
现在      你记 → 存下来 → 你自己翻（日历跳转 / 标签筛选 / 导出 Markdown）
他要的    你记 → 存下来 → 它下周主动告诉你一件你不知道的事
```

记录类产品的价值不在记的那一刻，在两周后它主动告诉你什么。
现在所有的回看入口都是「让你自己去找」。

**如果只让他改一件事，赌是这个：把首页从「流」变成「这周」。**

```
┌─────────────────────────┐
│ 这周                     │  ← 新增：吃了几顿外食、动了几次、
│ 外食 4 次 · 运动 2 次     │     身体记录里出现最多的词
│ 身体：胃胀 ×3            │
├─────────────────────────┤
│ 今天                     │  ← 下面才是现在这条流，一个字不用改
│  ○ 晚饭三文鱼 米饭 纳豆   │
└─────────────────────────┘
```

记录的动作一个字不改，回看的价值翻十倍。

## 明天的动作，按「先减后加」排

### 第一档：纯减法，改动小、马上能做

| 做什么              | 影响面                                        | 前置决定                             |
| ---------------- | ------------------------------------------ | -------------------------------- |
| 高光 / 摘抄 / 置顶 三合一 | `toggleMark` + 菜单 + 气泡样式 + 置顶条             | 保留哪一个的视觉？导出时摘抄的 blockquote 还要不要？ |
| 砍「多选」            | `enterSelect()`（index.html:2275）           | 批量删除还有别的入口吗？                     |
| 砍「回复串」           | `openThread()`（index.html:2024）+ `e.re` 字段 | 自己给自己回复，用过几次？                    |
| 砍「隐藏」            | `msk` 一路                                   | 给别人看屏幕的场景真实存在吗？                  |

### 第二档：定位问题，先回答再动手

1. Aside 是**身体日志**，还是**通用第二大脑**？（决定标签表砍不砍）
2. 「摘抄」这条线（OCR 扫书 → 摘抄标签 → blockquote 导出）保不保？
3. 云同步的地址和密钥还要用户手填吗？（试过预填地址，但这个仓库是公开的，
   写死自己那台 Worker 等于把端点挂出去，已经撤回。要省这一步得换个不进仓库的办法）

### 第三档：新功能，单开一轮

- **「这周」小结**：首页顶部一块，纯读现有数据算，不改任何写入路径
- 语音记录：现在核心动作是「打字 + 自动分类」，他大概率会问「为什么要打字」
